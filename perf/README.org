* talk-rs performance harness

A shared yardstick for the performance shortlist.  Every experiment (one
improvement per branch) is scored against the same cuts, the same
targets (~perf/targets.yaml~) and the same baseline
(~perf/baseline.yaml~, measured on unmodified master).

** For experiments: the acceptance command

#+begin_src sh
bin/perf-report --compare perf/baseline.yaml --item <item-id> --strict
#+end_src

This runs exactly what the item needs — its performance tests (ignored
ones included) and its prerequisite correctness tests — serially, then
scores the result.  It *accepts* (exit 0, ~perf: ACCEPTED~ on stderr)
only when:

- every cut listed for the item ran and produced its metrics;
- every non-advisory target of the item is ~met~;
- every prerequisite test of the item passed;
- nothing that ran is ~regressed~, ~missing~, ~failed~ or ~invalid~.

Rules for experiments:

1. Branch from ~perf/harness~.  Keep the counters: when you move work,
   move its counter with it (a shared HTTP client still counts
   ~http_client_builds~ where it is built; a memoised preparation still
   counts ~upload_encodes~ where it actually encodes).
2. Implement one item; never edit ~perf/targets.yaml~,
   ~perf/baseline.yaml~, the perf tests or their guards.  If the
   harness is wrong for your item, say so in your report.
3. Run the acceptance command on the machine the baseline was taken on
   (~host:~ in ~perf/baseline.yaml~).  Items with ~models:~ need the
   model variables set (see below).
4. ~kind: work~ lines are deterministic.  ~kind: timing~ lines are
   medians of ~--repeat~ runs (default 5) with ~-p90~, ~-spread~ and
   ~-n~ recorded next to them; if one is borderline, rerun with a
   larger ~--repeat~.
5. Paste the comparison output into the experiment report.

** Running

#+begin_src sh
bin/perf-report                               # default cuts, YAML report on stdout
bin/perf-report --all -o /tmp/me.yaml         # + long, display, model cuts and every prerequisite
bin/perf-report --compare perf/baseline.yaml  # run the default cuts, then score them
bin/perf-report --compare perf/baseline.yaml --report /tmp/me.yaml
bin/perf-score --help                         # the scorer on its own
bin/test-perf-report                          # the runner's own tests (sunit)
#+end_src

The runner builds the debug test binaries with ~--features
perf-counters~, runs every selection *serially* (timings are
meaningless under parallel load) and assembles one report: the run
manifest (~runs:~ — each test selection and whether it passed or
failed), skip notices, and the metrics of every cut.  ~--compare~
prints one line per target or guard:

#+begin_example
met       paste-focus-sleep already-focused focus-virtual-ms baseline=50 now=0 target="<= 5" delta=-50 kind=work
not-met   http-client-pool-prewarm transport-sequential-20 http-client-builds baseline=20 now=20 ...
regressed upload-normalize-once runtime-heartbeat-2min heartbeat-max-gap-ms ...
#+end_example

| Status      | Meaning                                                                                                             |
|-------------+---------------------------------------------------------------------------------------------------------------------|
| ~met~       | the criterion holds                                                                                                 |
| ~not-met~   | the criterion does not hold (and the metric is no worse than baseline)                                              |
| ~regressed~ | a guard does not hold, or the metric moved in its "worse" direction beyond noise, whether or not its target is met |
| ~missing~   | the cut ran but did not record the metric                                                                           |
| ~failed~    | the cut's test or a prerequisite failed, or it was selected and produced nothing                                   |
| ~skipped~   | the cut was not selected in this run                                                                                |
| ~invalid~   | non-numeric or non-finite value, or a relative criterion without a baseline value                                  |

A cut counts as selected — so that producing nothing makes it ~failed~
rather than ~skipped~ — when a run of a superset of its tests (libtest
filters match by substring) included ignored tests; the manifest
records ~ignored:~ per run (older manifests: a prerequisite run had
none, any other run had them).  With ~--item ID~ another item's cuts
count as selected only when that item's own test selections were run:
the prerequisites of ID never make a foreign cut ~failed~, so ~--strict~
judges ID's own cuts and prerequisites, plus any metric that ran.

Noise margins for regression: ~work~ 10 %; ~timing~ the largest of
25 %, 20 units, and twice the drift measured between two independent
baseline runs (the ~noise:~ map of ~perf/baseline.yaml~, written by
~bin/perf-score --calibrate FIRST SECOND~); an ~==~ target regresses
when a value the baseline satisfied is lost.  The direction is inferred from the criterion (~<=~ → higher
is worse) or set with ~worse:~.  Exit status: 0 success; 1 when
anything is ~regressed~ / ~missing~ / ~failed~ / ~invalid~ (or, with
~--strict~, the item is rejected); 2 on malformed input — the targets
file (entries, criteria, cut lists) and both reports are schema-checked,
and a report without its run manifest is refused.

Gating:

| Flag        | Adds                                                         | Needs                                                              |
|-------------+--------------------------------------------------------------+--------------------------------------------------------------------|
| (default)   | in-crate cuts, binary cuts with mock providers               | nothing                                                            |
| ~--display~ | overlay FFT cuts, ~record --ui~ on a 1500-recording library  | ~Xvfb~, or ~weston~ (headless + Xwayland)                          |
| ~--ignored~ | every ~#[ignore]~-d cut (long, display, model)               | as above; about 10 minutes                                         |
| ~--models~  | Parakeet and Kokoro cuts                                     | ~TALK_RS_TEST_PARAKEET_MODEL_DIR~, ~TALK_RS_TEST_KOKORO_MODEL_DIR~ |
| ~--all~     | all of the above plus every item's prerequisite tests        | as above                                                           |
| ~--item ID~ | exactly item ID's tests (ignored included) and prerequisites | whatever the item needs                                            |

Plain ~cargo test~ stays green without any of this: counter-reading
tests skip when the feature is off, heavy cuts are ~#[ignore]~-d.

** Isolation

Nothing touches the user's session.

- Binary cuts run ~talk-rs~ with a cleared environment (no inherited
  ~TALK_RS_*~ overrides or credentials), temporary ~HOME~ and ~XDG_*~
  dirs, their own ~TALK_RS_VALIDATE_CACHE_PATH~, the ALSA ~null~ PCM,
  unreachable PulseAudio/PipeWire sockets, and ~HTTP(S)_PROXY~ pointed
  at a closed port so any egress other than the harness's own loopback
  servers fails fast.
- The in-process heartbeat cut runs in a child of the test binary with
  the same cleared environment, and builds its ~Config~ by direct
  deserialisation (~Config::load~ would apply environment overrides).
- Display cuts start their own X server (Xvfb, else headless Weston +
  Xwayland, which also provides an EWMH window manager) and only ever
  signal that child.
- Model cuts first validate the directory with the production presence
  check (an incomplete directory *fails* the cut instead of letting
  talk-rs take its consent/download path) and assert afterwards that
  the model tree — including the sibling ~.lock~ file — is unchanged.
- Playback never opens an audio device: with ~TALK_RS_PERF_AUDIO_SINK~
  the shared ~AudioPlayer~ drives the same output callback from a
  10 ms-paced capturing sink.

** Harness pieces

- ~src/perf_counters.rs~ — work counters behind the ~perf-counters~
  feature.  Feature off: every counter, gauge and mark call is an empty
  inline function; marks whose name needs formatting go through
  ~mark_with~, whose closure is never evaluated; the focus seam passes
  the borrowed window id (no allocation).  Also live, per thread, in
  the crate's own unit tests.  The CLI writes one *framed* dump on exit
  and on ~SIGUSR2~: ~perf-dump-begin: id=N reason=… t=+Ms~, one
  ~perf-counter:~ line per value (counters, gauges and their maxima,
  ~vm_hwm_kb~, ~vm_rss_kb~, ~threads~, ~cpu_ms~, ~gtk_stall_max_ms~),
  then ~perf-dump-end: id=N fields=K~ — a single log record, and the
  parser rejects frames without a matching end marker and field count.
- ~TALK_RS_PERF_PACED_INPUT=<wav>~ (feature only) — replaces the
  microphone with a WAV replayed at real-time pace, so the live
  one-shot path (SIGINT stop, live upload, fallback) runs without
  hardware.
- ~TALK_RS_PERF_AUDIO_SINK=<path>~ (feature only) — the shared
  ~AudioPlayer~ opens no device; a thread consumes its buffer through
  the production ~fill_output~ callback at device pace, logs the first
  *meaningful* consumed sample (~first-audio +ms epoch= sample=~) and
  saves every consumed sample to ~<path>.pcm~.
- ~TALK_RS_PERF_UI_PROBE=<dir>~ (feature + ~ui~ only) — the recordings
  browser answers ~snapshot~, ~row <path>~ and ~click <path>~ commands:
  what each row shows (kind, text, waveform ready, selection, button
  state), and clicks on the real play button.
- ~FrameAnalysis~ (~src/x11/overlay.rs~) — the recording badge's
  per-frame detectors, peaks and visualizer histories, extracted from
  the render loop (proven identical to the original inline loop by a
  frozen transcription of it) so they can be driven with scripted
  frames.
- ~ensure_focus_with~ — the paste focus policy with the X11 calls
  injected, measured on a paused tokio clock.
- ~tests/perf/support/~ — fixtures (speech-like PCM; WAV/OGG in both
  profiles; a 1500-recording library with warm/stale/corrupt/missing
  ~.wf~ caches, M4A/MP4 imports, a 10-minute row and pick locks; long
  fixtures cached under ~target/perf-fixtures/~, keyed by generator
  version and verified by content hash), the isolated runner, strict
  Ogg Opus decoding and a content comparator for lossy audio, a
  wiremock provider behind a counting proxy that associates every
  request with the TCP connection that carried it, the isolated
  display, and the metric writer (~TALK_RS_PERF_OUT~; values must be
  finite and export errors fail the cut).

** Advisory targets (why they cannot decide alone)

- ~record-ui-row-work / idle-cpu-ms-per-s~: dominated by GTK and X
  housekeeping on a debug build; tick callbacks per second is the
  attributable measure.
- ~streaming-playback-decode / play-decode-1h~: the full-file decode
  helper keeps its contract (whole output) even when playback streams;
  its speed and buffer are diagnostics.  The Play-path cut
  (~play-long-row~) is the acceptance measure.
- ~overlay-fft-gating / spectrum-allocs-per-frame~: buffer reuse is an
  optional part of the item.
- ~parakeet-warm / chain-cloud-busy-parakeet-last~: an immediate cloud
  → Parakeet chain leaves almost no time to overlap a first-failure
  warm start.
- ~speak-streaming-playback / handoff-ms~: handing PCM to the player is
  not sound; ~first-sound-ratio~ (consumed by the output) is the
  acceptance measure.

** Refreshing the baseline

Run the full suite twice on an otherwise idle machine and calibrate:

#+begin_src sh
bin/perf-report --all -o /tmp/b1.yaml     # with the model variables set
bin/perf-report --all -o /tmp/b2.yaml
bin/perf-score --calibrate /tmp/b1.yaml /tmp/b2.yaml > perf/baseline.yaml
#+end_src

Then copy the new values into the informational ~baseline:~ fields of
~perf/targets.yaml~.  The committed baseline: host ~wen~, master
~4c48160~ plus this harness, debug build, repeat 5, two runs
(~noise-source~).  Display and model timings drifted up to ~3× between
the two runs (other jobs on the machine); the calibrated margins absorb
that for regression checks, and targets on those metrics are set far
from the baseline.

** Known limits

- Timings are debug builds on a shared developer machine; compare only
  runs from the baseline's host.  ~record --ui~ numbers include ~135
  concurrent waterfall decodes competing for the CPU.
- The paste cut measures the focus policy (virtual time), not an
  end-to-end X11 paste.
- Connection costs are emulated in the application (a proxy delaying
  each accepted connection), not as a TCP/TLS handshake; the proxy is
  not a connect-timeout blackhole (the refused-origin transport test
  covers the budget schedule).  Real TLS or VPN savings must be
  confirmed against a live provider.
- The OpenAI realtime cuts use a scripted server; whether the real
  service keeps the socket open after the final item must be confirmed
  live before shipping that item.
- The capturing sink runs at device pace but is not a device: audible
  latency of a real output (buffering, Bluetooth) is not included.
- Kokoro is not bit-deterministic across runs: played and saved audio
  are compared by duration and content envelope, not bytes.
