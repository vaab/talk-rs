Voice dictation for Linux. Record, transcribe, and paste text into any
application -- all from a single keyboard shortcut.

=talk-rs= captures audio from your microphone, sends it to a
transcription API (Mistral Voxtral or OpenAI Whisper), and types the
result into the focused window. A small X11 overlay badge shows the
current state (recording / transcribing) so you always know what is
happening.

** Features

- *Dictation workflow* -- press a key to start recording, press again
  to stop; transcribed text is pasted automatically.
  The original clipboard content (including non-text targets such as images)
  is restored after pasting and remains available after ~talk-rs~ exits until
  you copy something else. If there was no clipboard owner, nothing is restored.
- *Multiple providers* -- Mistral (Voxtral), OpenAI (Whisper / GPT-4o),
  and local on-device Parakeet for batch transcription; Mistral and
  OpenAI realtime streaming via WebSocket.
- *Text-to-speech* -- the ~speak~ command synthesizes text and plays
  it (or saves a WAV).  Two providers mirror the transcription side:
  ~kokoro~ (local, offline, multi-language via sherpa-onnx) and
  ~mistral~ (remote Voxtral TTS).  Language handling is config-driven
  and agnostic.
- *Speaker diarization* -- identify who is speaking (~--diarize~);
  output is tagged with speaker labels.  Currently supported with
  Mistral V2 models in batch mode.
- *Multi-candidate picker* -- with ~--pick~, run several providers in
  parallel and choose the best transcription from a GTK picker window.
  A waterfall spectrogram of the recording is shown above the
  candidate list; it loads asynchronously and adapts to window width.
  Non-default models are transcribed on demand via a per-candidate
  button to avoid unnecessary API calls.  Previous/next recording
  arrows beside the player move through the current cache or recordings
  collection in newest-first order, saving edits before each move.  Arrow
  navigation never auto-transcribes; click ~T~ to transcribe a recording.
- *Visual overlay* -- non-intrusive X11 badge at the top of the screen
  (works without a compositor).
- *Live transcription overlay* -- a dynamic phase-coloured waterfall
  replaces the static "transcribing" badge; three independent
  throughput tracks (upload bytes, download bytes, paste characters)
  show progress through the pipeline, with a time-grid layer over the
  spectrogram.
- *Dead audio detection* -- overlay badge shows a red prohibit icon
  and "NO SOUND" warning when no real microphone is detected (e.g.
  headset unplugged); a centered full-screen overlay and repeating
  alert tone reinforce the signal, and a notification also appears on
  the text panel.
- *Auto-pause* -- automatically pauses audio forwarding during
  silence, trimming dead air from transcription input.  Resumes
  instantly with a 300 ms lookback buffer to preserve speech onset.
  The badge shows yellow pause bars and "LISTENING" during pauses.
  Disable with ~--no-auto-pause~.
- *Audio visualizers* -- optional in-badge visualization during
  recording (~--viz waterfall~, ~--viz amplitude~, ~--viz spectrum~);
  monochrome mode with ~--mono~.
- *Audio feedback* -- start/stop tones plus a periodic boop while
  the badge shows ~LISTENING~ (i.e. during auto-pause silence); the
  boop is silent while you are actively speaking, and is never heard
  when ~--no-auto-pause~ is used.  Fully configurable or disabled.
- *Bluetooth headset auto-switch* -- when a Bluetooth headset is
  connected in A2DP mode (high-quality stereo, no microphone),
  ~talk-rs~ automatically switches it to its Hands-Free Profile (HFP)
  for the duration of the recording so the headset microphone is
  available, then restores the original profile on stop.  Survives
  unclean termination: a state file at
  ~$XDG_RUNTIME_DIR/talk-rs/card-profile.json~ is written before the
  switch, and the next invocation restores the original profile from
  that file before starting a new recording.  Works with any HFP-capable
  headset (uses PulseAudio's standard ~device.form_factor~ property,
  not vendor-specific identifiers).  Disable per-invocation with
  ~--no-bt-auto-switch~ or globally via the
  ~audio.bt_auto_switch~ config key.
- *Context bias* -- supply domain-specific vocabulary to improve
  transcription accuracy.
- *Daemon toggle mode* -- first invocation spawns a short-lived daemon
  that records; second invocation signals it to stop, transcribe,
  paste, and exit.  Ideal for global shortcuts.
- *No idle dictation daemon* -- the toggle daemon spawns on press,
  records, and exits after pasting. Only a tiny background clipboard
  holder may remain; it exits as soon as another app takes the clipboard.
- *Retry last* -- re-transcribe the last cached recording without
  speaking again (~--retry-last~).
- *Recordings browser* -- ~record --ui~ opens a GTK4 window listing
  all recordings (OGG from ~output_dir~) and dictation cache (OGG).
  Imported audio dropped into ~output_dir~ -- ~.m4a~, ~.mp4~, or
  ~.aac~ (e.g. iPhone voice memos) -- is listed and playable
  alongside native OGG recordings, with the same waterfall and
  transcription workflow.
  Play, delete, open in the file manager, or transcribe on demand.
  A waterfall spectrogram is shown for every recording, even those
  without transcripts; sections auto-refresh via inotify when files
  change externally.
- *Per-segment timing export* -- ~--output-yaml~ includes per-segment
  start/end timestamps in the metadata sidecar, suitable for
  subtitles and post-processing.
- *Standalone commands* -- ~record~ and ~transcribe~ can be used
  independently for scripting.
- *Environment overrides* -- every config value can be set via
  ~TALK_RS_*~ environment variables.

** Prerequisites

*** Build dependencies

#+begin_src sh
# Debian / Ubuntu
sudo apt install build-essential pkg-config libasound2-dev libopus-dev \
  libgtk-4-dev libpipewire-0.3-dev libspa-0.2-dev libclang-dev \
  libpulse-dev

# Fedora
sudo dnf install alsa-lib-devel opus-devel pkg-config \
  gtk4-devel pipewire-devel spa-devel clang-devel \
  pulseaudio-libs-devel
#+end_src

~libpulse-dev~ / ~pulseaudio-libs-devel~ provides the PulseAudio client
library used to switch a Bluetooth headset's PulseAudio card profile
between A2DP (high-quality stereo) and HFP (microphone-enabled) when
recording.  On PipeWire systems, ~pipewire-pulse~ supplies the
~libpulse.so~ shared object at runtime, so no PulseAudio daemon is
needed -- only the development headers for compilation.

A working Rust toolchain is required (1.87+). Install via
[[https://rustup.rs][rustup]] if needed.

*** Runtime dependencies

=PipeWire= must be running (used for audio capture). Most modern Linux
desktops ship with PipeWire by default.

Cloud transcription providers require an API key:

- [[https://console.mistral.ai/][Mistral]] (default)
- [[https://platform.openai.com/][OpenAI]]

Parakeet is a local, on-device ASR backend using sherpa-onnx on the
CPU and needs no API key.  After a consent prompt, its model is
downloaded on first use into ~~/.local/share/talk-rs/models/~.
Downloaded Parakeet and Kokoro models include a ~.complete~ file with
required-file sizes; changed sizes cause a fresh consent-gated download.
Older manually installed models without this file retain the legacy
non-empty-file check because the release specs do not include exact
sizes or checksums. The approximate download sizes are only estimates.

** Installation

With the build dependencies above installed, install the latest
release from crates.io:

#+begin_src sh
cargo install --locked talk-rs
#+end_src

The binary lands in ~~/.cargo/bin/~, which rustup puts on your
~$PATH~.

If building from a git clone, run ~./autogen.sh~ first to resolve
version placeholders in ~Cargo.toml~:

#+begin_src sh
./autogen.sh
cargo build --release
#+end_src

The binary is at ~target/release/talk-rs~. Copy it somewhere in your
~$PATH~:

#+begin_src sh
cp target/release/talk-rs ~/.local/bin/
#+end_src

** Configuration

=talk-rs= reads ~$XDG_CONFIG_HOME/talk-rs/config.yaml~ (typically
~~/.config/talk-rs/config.yaml~).

Copy the example and fill in your values:

#+begin_src sh
mkdir -p ~/.config/talk-rs
cp config.example.yaml ~/.config/talk-rs/config.yaml
#+end_src

Minimal working configuration:

#+begin_src yaml
output_dir: ~/talk-rs-output

providers:
  mistral:
    api_key: YOUR_MISTRAL_API_KEY
#+end_src

*** Required fields

| Field                        | Description                                          |
|------------------------------+------------------------------------------------------|
| ~output_dir~                 | Absolute path to a writable directory for recordings (a leading ~~~ is expanded to your home) |
| ~providers.mistral.api_key~  | Mistral API key (if the section exists; YAML or ~TALK_RS_PROVIDERS_MISTRAL_API_KEY~) |
| ~providers.openai.api_key~   | OpenAI API key (if the section exists; YAML or ~TALK_RS_PROVIDERS_OPENAI_API_KEY~) |

The ~recording.*~ settings control the quality of recordings meant
for a *human* to listen to or share.  They are independent of
transcription: audio sent to the providers is always downsampled to
16 kHz mono internally (both Voxtral and Whisper operate at 16 kHz),
so these knobs do not affect transcription accuracy or upload size.

*** Named transcription fallback chains

Add named chains under ~transcription.chains~; ~default_chain~ selects one
when neither ~--chain~ nor an explicit ~--provider~ / ~--model~ is used.
It is either a single chain name used by every command, or a map from
command (~dictate~, ~transcribe~) to chain name, e.g.
~default_chain: {dictate: dictate, transcribe: transcribe}~; a command
missing from the map has no default chain.
Both ~dictate~ (including ~--toggle~) and ~transcribe~ accept ~--chain
NAME~ and ~--lang CODE~.  ~--chain~ conflicts with ~--provider~ and
~--model~.  Explicit single-model calls keep their existing behavior.

#+begin_src yaml
transcription:
  default_chain: dictate
  outage_memory: 3m
  chains:
    dictate:
      - mistral/voxtral-mini-2602
      - model: openai/gpt-transcribe
        retries: 2
      - model: mistral/voxtral-mini-2507
        wait: 45s
      - parakeet
    french:
      - model: openai/gpt-transcribe
        languages: [fr]
      - mistral/voxtral-mini-2602
    experimental:
      - model: mistral/some-future-model
        supports: [diarize, realtime]
#+end_src

An entry is either ~provider/model~, a bare provider (its configured
batch model), or a map with ~model~ and optional ~retries~, ~wait~,
~languages~ and ~supports~.  Durations use ~s~ or ~m~ (e.g. ~30s~,
~2m~).  Without patience, the first busy failure moves immediately to
the next model, including at the final entry.  When both bounds are
set, the earlier bound wins.  The transport continues to honor
~Retry-After~.  Only HTTP 429/5xx and connection/timeouts advance;
bad credentials, unknown models and other permanent errors stop the
chain.  Successful entries determine the sidecar/pick model and the
recording metadata includes an ~attempts~ list.

Chains are checked at config load: unknown/missing providers, missing
API keys, empty/duplicate entries, invalid durations and local
Parakeet before another entry are errors.  Before recording, ~--diarize~
and ~--realtime~ filter unsupported models.  A ~languages~ list is a
hard filter: without ~--lang~ that entry is skipped; with ~--lang fr~
only entries accepting French remain (unrestricted entries accept any
language).  ~supports~ can declare capabilities of future models;
known models retain their catalog facts.  If none remain, dictation
refuses before capture.  A chain in ~--pick~ lists its models first.

A chain never downloads the local Parakeet model: reaching it is a
fallback, not a choice to install ~640 MB.  If the model is missing,
the entry is skipped (recorded as ~not installed~ in ~attempts~), and
when nothing else can answer the error says how to install it once:
~talk-rs transcribe --provider parakeet <audio-file>~.

On a busy response, provider-wide outage memory is written atomically
to ~$XDG_CACHE_HOME/talk-rs/outages.yml~ (typically
=~/.cache/talk-rs/outages.yml=).  Subsequent runs skip that provider
until the ~Retry-After~ duration or ~outage_memory~ expires; if every
eligible provider is marked busy, they are still attempted in order.
Success clears its marker.  A corrupt file is ignored with a warning.

Whenever ~dictate~ transcribes with any entry other than the chain's
first one, the text panel below the badge shows a persistent amber
line naming the model in use and the primary one, e.g. ~⚠
gpt-transcribe (voxtral-mini-2602 unavailable)~.  It appears as soon
as the fallback is known (at start when the primary is in outage
memory, at the switch otherwise) and stays until the dictation ends.

*** Foreground application paste routing

The recursive ~paste:~ tree supports ~match-foreground-app~ beneath
the ~@terminal~ WM_CLASS group.  It resolves the application attached
to the remembered terminal surface immediately before dispatch.

Only a positively identified interactive ~opencode~ process, or an
~opencode attach URL~ process, receives the ~opencode-tui~ label.
Server, run, SSH, copy-mode, ambiguous multi-surface, permission, and
timeout cases use the configured default branch.  Global flags before
~attach~ are intentionally classified as unknown rather than guessed.

The example in ~config.example.yaml~ keeps GUI paste on ~ctrl_v~ and
terminal paste on ~ctrl_shift_v~.  Only ~opencode-tui~ receives the
150-character chunk decorator; Pi, Emacs, shells, and unknown targets
remain unchunked.  Kitty remote control is never enabled; a Kitty
process exposing multiple PTYs therefore remains unknown.

*** OpenAI model migration

The OpenAI batch default is exactly ~gpt-transcribe~, and the realtime
default is exactly ~gpt-live-transcribe~.  Existing configuration files
remain valid: ~prompt~, ~keywords~, ~languages~, and ~realtime_delay~ are
optional, and omitting them sends no hint fields.

- ~gpt-transcribe~ sends ~prompt~, repeated ~keywords[]~, repeated
  ~languages[]~, and ~response_format=json~ to the batch endpoint.
- ~gpt-live-transcribe~ nests ~model~, ~prompt~, ~keywords~,
  ~languages~, and ~delay~ under
  ~session.audio.input.transcription~ in the realtime ~session.update~.
- ~whisper-1~ remains available for segment/word timestamps, subtitles,
  and translation workflows.  It retains ~response_format=verbose_json~,
  accepts ~prompt~ and one unambiguous singular ~language~, and does not
  accept ~keywords~ or multiple languages.
- ~gpt-4o-transcribe~ and ~gpt-4o-mini-transcribe~ remain available as
  legacy batch choices.  ~gpt-realtime-whisper~ remains available as a
  legacy realtime choice, using singular ~language~ for one expected
  language and rejecting ~keywords~, multiple languages, and
  ~realtime_delay~.

Configured hints that the selected model cannot represent fail locally
before HTTP or WebSocket traffic; talk-rs never silently drops them.
There is no structured previous-turn configuration field in the official
schema.  Earlier-turn context is service-managed where supported.

Direct-OpenAI prices checked 2026-07-31: ~gpt-transcribe~ costs
$0.0045/min ($0.27/hr), while ~whisper-1~ costs $0.006/min ($0.36/hr).
The new batch default is 25% lower, a $0.09 per hour savings.

*** Environment overrides

Every config value can be overridden via environment variables:

#+begin_src sh
export TALK_RS_PROVIDERS_MISTRAL_API_KEY="sk-..."
export TALK_RS_PROVIDERS_OPENAI_API_KEY="sk-..."
export TALK_RS_PROVIDERS_OPENAI_PROMPT="Preserve punctuation and casing."
export TALK_RS_PROVIDERS_OPENAI_KEYWORDS="Kalysto, talk-rs"
export TALK_RS_PROVIDERS_OPENAI_LANGUAGES="fr, en"
export TALK_RS_PROVIDERS_OPENAI_REALTIME_DELAY="low"
export TALK_RS_INDICATORS_MONO="true"
#+end_src

For a configured ~providers.mistral~ or ~providers.openai~ section, its
~api_key~ may be omitted from YAML when the corresponding environment
variable supplies it.  If neither supplies a key, loading fails and
names both the YAML field and environment variable.  An environment
key can also create a provider section absent from YAML.

~TALK_RS_PROVIDERS_OPENAI_KEYWORDS~ and
~TALK_RS_PROVIDERS_OPENAI_LANGUAGES~ are comma-separated lists.  talk-rs
trims whitespace and ignores empty entries deterministically; environment
values override YAML in both existing and environment-created OpenAI
sections.

See ~config.example.yaml~ for the full list.

*** Global options

| Flag                | Effect                                                                                                |
|---------------------+-------------------------------------------------------------------------------------------------------|
| ~-v~                | Increase logging verbosity (~-vv~ debug, ~-vvv~ trace)                                                |

*** Dictate (main workflow)

Record, transcribe, and paste into the focused application:

#+begin_src sh
talk-rs dictate
#+end_src

Toggle mode (ideal for keyboard shortcuts):

#+begin_src sh
talk-rs dictate --toggle
#+end_src

First call starts a background daemon that records. Second call stops
recording, transcribes, and pastes the result.

Options:

| Flag                        | Effect                                          |
|-----------------------------+-------------------------------------------------|
| ~--toggle~                  | Daemon toggle mode                              |
| ~--provider~                | Choose ~mistral~, ~openai~, or ~parakeet~       |
| ~--model~                   | Override model for this invocation               |
| ~--chain <NAME>~            | Use a named fallback chain (conflicts with ~--provider~ and ~--model~) |
| ~--lang <CODE>~             | Request a language code and filter chain entries |
| ~--diarize~                 | Enable speaker diarization (batch mode only)    |
| ~--timestamp~               | Include timestamps in output (~HH:MM:SS~ prefix) |
| ~--realtime~                | Stream audio via WebSocket (incremental text)   |
| ~--pick~                    | Show multi-candidate picker (GTK window)        |
| ~--retry-last~              | Re-transcribe the last cached recording (conflicts with ~--input-audio-file~) |
| ~--replace-last-paste~      | Delete previous paste before inserting new text |
| ~--save <PATH>~             | Save audio even on transcription failure; create parent directories and report copy errors |
| ~--output-yaml <FILE>~      | Write transcription metadata YAML               |
| ~--input-audio-file <FILE>~ | Feed a pre-recorded audio file instead of live mic |
| ~--monitor~                 | Mix system audio (monitor) with mic input       |
| ~--no-sounds~               | Disable audio indicators                        |
| ~--no-boop~                 | Disable periodic boop sounds (keep start/stop)  |
| ~--no-chunk-paste~          | Paste all text in one shot (disable chunking)    |
| ~--no-overlay~              | Disable visual overlay                          |
| ~--no-auto-pause~           | Disable auto-pause during silence (forward all audio) |
| ~--no-paste~                | Skip pasting transcription into the focused application |
| ~--upload-format <FORMAT>~  | Audio format for batch uploads: ~wav~ (default) or ~ogg~ |
| ~--viz <MODE>~              | In-badge visualizer: ~waterfall~, ~amplitude~, or ~spectrum~ |
| ~--mono~                    | Monochrome visualizer (theme-aware)             |
| ~--no-bt-auto-switch~       | Disable Bluetooth headset HFP auto-switch (overrides ~audio.bt_auto_switch~) |

In ~--realtime~ mode, ~--no-paste~ also suppresses incremental pastes.
For a cached pick opened with ~--input-audio-file~ or ~--retry-last~,
~--no-paste~ skips delivery while ~--save~ and ~--output-yaml~ still
export audio and metadata. Confirming a saved selection in the picker
pastes into the current target: the saved pick records a choice, not
prior delivery.
~--replace-last-paste~ removes the previous text only in the same
target window, before the first segment; later segments append. If a
reconnected provider revises an already-pasted segment, the cached
transcript records the correction without pasting a duplicate. After
audio ends, realtime providers wait at most 15 seconds for final text.

*** Record

Capture audio to an OGG/Opus file:

#+begin_src sh
talk-rs record                       # auto-named <output_dir>/YYYY/MM/YYYY-MM-DDTHH-MM-SS±ZZZZ.ogg
talk-rs record meeting-notes.ogg     # custom filename
talk-rs record --toggle              # first call starts, second call stops
talk-rs record --toggle meeting.ogg  # toggle with an explicit output path
#+end_src

Toggle mode starts a background recorder on the first call.  The second
call sends SIGINT; the recorder stops capture, finalizes and syncs the
audio file, then exits.  Its PID remains published during finalization,
so repeated stop calls cannot start a second writer for the same toggle
slot.  Toggle mode conflicts with ~--ui~.

Foreground and toggle recording use the same feedback as dictation: the
optional X11 badge appears first, as soon as the shortcut is handled; the
start tone then finishes before capture begins; the badge visualizes the
captured PCM, and the periodic boop sounds only while the badge detects
silence.  On stop, the boop and badge are torn down before capture closes.
The stop tone sounds only after the encoder has finalized the file and
~sync_all()~ has made it durable.  If X11 is unavailable, recording and
sound feedback continue without the badge.

Options:

| Flag                  | Effect                                           |
|-----------------------+--------------------------------------------------|
| ~--toggle~            | Toggle background recording on the first/second call |
| ~--monitor~           | Mix system audio (monitor) with microphone input |
| ~--no-sounds~         | Disable start, stop, and boop sounds             |
| ~--no-boop~           | Disable silence-gated boops (keep start/stop)    |
| ~--no-overlay~        | Disable the recording badge                      |
| ~--viz <MODE>~        | In-badge visualizer: ~waterfall~, ~amplitude~, or ~spectrum~ |
| ~--mono~              | Monochrome visualizer (theme-aware)              |
| ~--ui~                | Open GTK4 recordings browser (play, delete, open folder) |
| ~--no-bt-auto-switch~ | Disable Bluetooth headset HFP auto-switch (overrides ~audio.bt_auto_switch~) |

Toggle state is stored under ~$XDG_CACHE_HOME/talk-rs/~ (normally
~~/.cache/talk-rs/~).  Dictation keeps its existing ~daemon.pid~,
~daemon.lock~, and ~daemon.log~ files.  Standalone recording uses the
separate ~record.pid~, ~record.lock~, and ~record.log~ files, so the two
commands cannot stop or overwrite each other's toggle state.

*** Transcribe

Transcribe an existing audio file:

#+begin_src sh
talk-rs transcribe recording.ogg                # print to stdout
talk-rs transcribe recording.ogg output.txt     # write to file
talk-rs transcribe recording.ogg --provider openai
talk-rs transcribe voice-memo.m4a               # imported m4a also works
#+end_src

Options:

| Flag          | Effect                                            |
|---------------+---------------------------------------------------|
| ~--provider~  | Choose ~mistral~, ~openai~, or ~parakeet~         |
| ~--model~     | Override model for this invocation                 |
| ~--chain <NAME>~ | Use a named fallback chain (conflicts with ~--provider~ and ~--model~) |
| ~--lang <CODE>~ | Request a language code and filter chain entries |
| ~--diarize~   | Enable speaker diarization (tag by speaker)       |
| ~--timestamp~ | Include timestamps in output (~HH:MM:SS~ prefix)  |

Transcription sidecars are reused only while the audio file exists and
its size and modification time match the saved values. Older sidecars
without those fields remain readable for existing audio files. Model
names with slashes or spaces are escaped in new sidecar filenames;
ordinary model names keep their existing filenames.

**** Provider overload

Cloud providers periodically answer =503 high load= or
=429 backend_out_of_capacity=, especially on long recordings.
For a single-model call, ~talk-rs~ treats every 5xx and 429 as "busy,
try again later" and waits between attempts: 5 s, 15 s, 30 s, 60 s, 120 s, 120 s (about
5.5 minutes in total, seven attempts).  A =Retry-After= header from
the provider (seconds or HTTP date) overrides the schedule slot (capped at 120 s).  Each wait
is logged at ~-v~ as =server retry N/6=.  Other 4xx answers are
permanent and fail immediately.

Connection failures (DNS, unreachable host, TLS timeout) use a
separate, shorter schedule and never consume the server-retry
budget.  Large uploads are given the whole request time budget on
every attempt, so an 80-minute recording is not cut off by the early
connection slots.
In the interactive picker, a connected request has no per-request
wall-clock cap: slow server processing does not cause the same paid
transcription POST to be sent again.

If all seven single-model attempts fail the recording is kept in the cache;
re-run ~transcribe~ on the ~.ogg~ (or ~dictate --retry-last~) once
the provider has recovered.

*** Speak (text-to-speech)

The architectural mirror of ~transcribe~: text in, speech out.
Synthesize text and play it through the speakers, or save it to a
WAV file.  Two providers -- ~kokoro~ (local, offline, on-device via
sherpa-onnx) and ~mistral~ (remote Voxtral TTS).

#+begin_src sh
talk-rs speak "hello world"                        # synthesize + play
talk-rs speak --provider mistral --voice <id> "hi" # remote Voxtral TTS
talk-rs speak -o out.wav "save me to a file"       # write WAV, don't play
echo "from a pipe" | talk-rs speak                 # read text from stdin
talk-rs speak -f message.txt                       # read text from a file
talk-rs speak --lang fr --voice ff_siwis "Bonjour" # French (Kokoro)
#+end_src

Text is resolved in priority order: the positional argument, then
~--file~, then stdin (when stdin is not a TTY).

The default provider is resolved as ~--provider~ >
~speak.default_provider~ (config) > the local ~kokoro~ backend when a
~providers.kokoro~ section exists, else ~mistral~.  On first use the
Kokoro model (~350 MB) is downloaded after an interactive consent
prompt (or a non-interactive proceed-with-log, exactly like the
Parakeet ASR model) into
~~/.local/share/talk-rs/models/kokoro-multi-lang-v1_0/~.

Options:

| Flag                | Effect                                                                 |
|---------------------+------------------------------------------------------------------------|
| ~--provider~        | Choose ~kokoro~ (local) or ~mistral~ (remote Voxtral)                   |
| ~--voice~           | Kokoro voice name (~af_heart~, ~am_michael~, ~ff_siwis~, …) or a Mistral preset voice id |
| ~--lang~            | Language for Kokoro phonemization; for Mistral, selects/validates the preset voice (auto-detected from the text when omitted) |
| ~--speed~           | Speech rate multiplier for Kokoro (~1.0~ = normal)                     |
| ~-f~, ~--file~      | Read the text to speak from a file                                     |
| ~-o~, ~--output~    | Save synthesized audio to a WAV file instead of playing it             |
| ~--force~           | Bypass the voice/language mismatch guard                               |

Language handling is config-driven and agnostic: the requested
language selects the phonemizer.  The stock Kokoro model ships one
baked language; other languages are derived on demand by patching the
model's ONNX ~voice~ metadata, cached as ~model-<lang>.onnx~ next to
the stock model.

*** Supported input audio formats

Commands that read audio from disk -- ~transcribe~,
~dictate --input-audio-file~, ~dictate --retry-last~, and the
~record --ui~ recordings browser -- accept the following formats:

| Extension      | Container / codec  | How it is handled                                          |
|----------------+--------------------+------------------------------------------------------------|
| ~.ogg~         | Ogg Opus           | Native format written by ~talk-rs record~                  |
| ~.m4a~ / ~.mp4~ | MP4 / AAC          | Decoded via [[https://github.com/pdeljanov/Symphonia][symphonia]]; ideal for iPhone voice memos and similar imports |
| ~.aac~         | Raw AAC stream     | Decoded via symphonia                                      |
| ~.wav~         | 16-bit PCM         | Decoded directly; primarily used for legacy cache entries |

Imported files keep their original extension on upload, so the
~transcribe~ command sends ~.m4a~ to the provider as-is -- both
Mistral Voxtral and OpenAI Whisper accept these natively. Playback
and waterfall spectrograms in the records browser work for every
listed format.

** GNOME keyboard shortcut

Bind ~talk-rs dictate --toggle~ to a key (e.g. =Super+/=):

#+begin_src sh
BASE="org.gnome.settings-daemon.plugins.media-keys"
BPATH="/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings"

CURRENT=$(gsettings get "$BASE" custom-keybindings)
N=0
while echo "$CURRENT" | grep -q "custom${N}/"; do
  N=$((N + 1))
done
SLOT="${BPATH}/custom${N}/"
SCHEMA="${BASE}.custom-keybinding:${SLOT}"

if [ "$CURRENT" = "@as []" ]; then
  gsettings set "$BASE" custom-keybindings "['${SLOT}']"
else
  gsettings set "$BASE" custom-keybindings "$(echo "$CURRENT" | sed "s|]$|, '${SLOT}']|")"
fi

gsettings set "$SCHEMA" name    'talk-rs dictate'
gsettings set "$SCHEMA" command 'talk-rs dictate --toggle --viz waterfall'
gsettings set "$SCHEMA" binding '<Super>slash'
#+end_src

First press starts recording, second press stops, transcribes, and
pastes into the focused application.

To change the key, replace ~<Super>slash~ with the desired binding
(e.g. ~<Super>semicolon~, ~<Super>d~). Add ~--realtime~ to use
streaming transcription instead of batch mode.

*** Automatic paste keyboard safety

Before sending a paste shortcut, =talk-rs= waits briefly while any
shortcut key is down or any non-lock server modifier slot is active.
This includes custom mappings and AltGr. If the keyboard remains busy,
the paste aborts with an error instead of resetting modifier state or
injecting into an ambiguous state. CapsLock and NumLock remain
unchanged; pressing either lock key during the wait also defers the
shortcut. A failed target window refocus aborts the retry attempt.

When a target window is known, chunked clipboard pastes retry a shortcut
only if that target has not fetched the chunk at all. If it fetched the
chunk fewer times than expected, pasting aborts rather than risking a
duplicate. =--replace-last-paste= only deletes earlier text when its
stored window ID matches the current paste target.

Every synthesized key request is checked with the X server. On success,
=talk-rs= releases its chord in reverse order; on failure, it attempts
release requests for every key it may have injected. X11 does not
provide an atomic keyboard transaction: physical input, focus changes,
grabs, or keymap changes can still interleave after the final state
check. A process kill or X server disconnect can likewise prevent
cleanup.
